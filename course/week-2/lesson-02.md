# 第 8 课：HTTP、arXiv API 与数据契约

## 本课产物

通过 arXiv 官方 API 获取“semantic communication”相关论文，并转换成项目自己的统一论文结构。

## 设计原则

采集器只负责外部世界，其他模块只依赖内部数据契约。这是从大型 Agent 框架中吸收的组件边界思想：外部格式变化时，不应迫使报告生成器一起重写。

## 实践任务

1. 先在浏览器或工具中观察一次 arXiv 响应。
2. 明确查询词、时间范围、排序规则、最大条数和超时。
3. 把 Atom/XML 响应解析为统一 `Paper` 数据。
4. 对非 2xx、超时、空响应和解析失败给出明确错误。
5. 保存一份去除隐私和动态字段的测试样例。

边界要求：优先官方 API，不用浏览器自动化抓取 arXiv 页面；设置清晰的 User-Agent、合理超时和温和请求频率。

## 验收

- [ ] 查询参数可以配置，代码中没有散落的魔法数字。
- [ ] 外部响应不会直接流入渲染器。
- [ ] 网络失败不会留下伪装成成功的空周报。
- [ ] 能解释 HTTP 状态码、超时和解析错误的区别。

交付证据：一份脱网可读的样例响应、转换后的 3 篇论文数据，以及错误场景截图或测试结果。
