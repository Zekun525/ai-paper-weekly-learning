# 第 10 课：测试、Mock 与失败处理

## 借鉴并融合

借鉴成熟 Agent 项目的可测试边界：网络、模型和时间都是不稳定依赖，必须能替换；核心转换和渲染应当是可重复验证的纯逻辑。

## 本课产物

为采集、解析、去重和渲染建立自动测试，并证明断网时仍能测试主要功能。

## 测试清单

- 正常响应解析；
- 空结果；
- 超时；
- 非 2xx；
- XML 损坏；
- 重复论文；
- 特殊字符和中文；
- 固定输入生成稳定报告；
- 写文件失败不覆盖上一份成功报告。

不要 Mock 自己的所有内部逻辑。Mock 应位于网络、时间、文件系统特殊故障等边界；内部模块最好通过真实数据一起工作。

## 第 2 周验收

从空环境开始：安装项目、运行测试、用样例生成报告、再用真实 API 生成报告。断开网络后，样例模式与测试仍应通过。

通过标准：

- [ ] 一条命令运行全部测试。
- [ ] 失败信息指出哪个边界出了问题。
- [ ] 真实网络测试与默认快速测试分离。
- [ ] README 写明安装、样例运行和测试方法。

完成后，你已经拥有“非 AI 版”的可靠周报。第 3 周只是在稳定管道中增加智能组件。
