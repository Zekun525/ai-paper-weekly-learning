# 第 13 课：研究型 Agent 状态机

## 借鉴并融合

借鉴 [DeerFlow](https://github.com/bytedance/deer-flow) 的长流程研究思想，把一次周报任务拆成可观察、可恢复的阶段；不照搬它的完整多 Agent 技术栈。

## 本课产物

实现一条显式工作流：

```text
计划查询 → 采集 → 规范化 → 筛选 → 单篇摘要 → 跨篇综合 → 引用校验 → 渲染 → 发布候选
```

## 状态设计

每阶段至少记录：输入摘要、输出位置、开始/结束时间、状态、失败原因和重试次数。失败后能从最近的有效快照恢复，而不是重复调用所有外部服务。

工具必须受限：

- 只允许预先注册的工具；
- 参数使用明确结构；
- 为网络和模型调用设置超时；
- 限制论文数量、重试次数和总成本；
- 发布步骤与研究步骤分离，默认只生成候选报告。

## 验收

- [ ] 日志能指出任务停在哪个阶段。
- [ ] 摘要阶段中断后可从规范化快照恢复。
- [ ] 超过预算或重试上限会安全停止。
- [ ] 同一输入不会重复发布同一期周报。

解释题：这条流程什么时候需要真正的 Agent 决策，什么时候普通确定性程序更可靠？
