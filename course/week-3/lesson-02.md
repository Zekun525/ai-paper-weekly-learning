# 第 12 课：RAG、引用与证据链

## 本课产物

让每条周报结论都能回到论文来源，并实现一个小规模、可解释的检索流程。

## 先区分两个任务

- 单篇论文摘要：上下文就是该论文元数据和摘要，不需要为了“像 AI 项目”而强行加向量数据库。
- 跨论文主题综述：需要从多篇论文中检索证据，再综合回答，这才是本项目的 RAG 场景。

## 实践任务

1. 给每篇论文保留稳定 ID 和原文 URL。
2. 建立最小检索器：先用关键词或简单相似度，再决定是否需要向量检索。
3. 生成“本周主题观察”时，同时输出引用的论文 ID。
4. 验证引用 ID 必须存在于本周数据集中。
5. 找不到证据时输出“不足以判断”，不编造引用。

## 验收

- [ ] 每条跨论文结论至少有一个可点击来源。
- [ ] 引用校验能拦截不存在的论文 ID。
- [ ] 能用相同问题比较无检索与有检索的答案。
- [ ] 能解释为什么当前数据量可能不需要向量数据库。

借鉴 LangChain 的检索组件边界，但保留一个自己写的最小实现；只有当需求证明必要时，才引入框架适配器。
