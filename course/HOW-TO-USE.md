# 这套学习仓库怎么用

这是一套边学边建设项目的课程，不是一次性阅读材料。课程内容已经规划完整，但 AI 周报成品要由你按 18 课逐步实现；这样 Git 历史能真实展示你的学习和工程能力。

## 第一次开始

1. 打开终端，确认位置是 `D:\ailearning`。
2. 阅读 [课程说明](README.md) 和 [完整路线](roadmap.md)，但不要提前执行后续课任务。
3. 打开 [第 1 课](week-1/lesson-01.md)。
4. 先回答课内“预测”，再逐条运行命令。
5. 完成闯关后，把该课要求的验收材料发给老师或 Codex。
6. 只有在你能解释原理且验收通过后，才勾选 [进度表](progress.md) 并进入下一课。

## 每次学习的固定循环

```text
读目标 → 先预测 → 做最小示范 → 独立闯关 → 提交证据 → 解释原理 → 验收通过 → 勾选进度
```

每次只做一课，推荐 60～120 分钟。不要一次粘贴全部命令，也不要为了赶进度直接复制高星项目代码。

## 如何向 Codex 求助

开始一课时可以发送：

```text
我要开始第 N 课。请先检查我当前仓库状态，然后按课程顺序指导我；不要替我完成闯关，也不要提前进入下一课。
```

卡住时发送：

```text
我在第 N 课的【具体步骤】卡住了。
我预测：【你的预测】
我运行了：【完整命令】
完整输出：【原样粘贴】
我的猜测：【你的猜测】
请先帮我理解原因，再给一个最小的下一步，不要直接完成整课。
```

申请验收时发送：

```text
请验收第 N 课。下面是课程要求的输出和我的原理解释。请逐项判断是否通过；未通过时只指出证据不足或理解错误的地方。
```

## 文件应该放在哪里

第 1 周只修改课程、学习记录和 Git 历史。进入第 2 周后，按课程逐步创建：

```text
src/paper_weekly/     自己实现的周报程序
tests/                自动测试
data/samples/         可公开的最小样例
reports/              周报产物
.github/workflows/    第 4 周自动化
```

不要提前创建空目录来“完成结构”；让每个目录随对应课程的真实代码一起进入 Git 历史。

## 参考项目怎么用

课程已把高星项目中适合的设计融合进任务。你只需在对应课中查看指定项目的 README 或一个最小调用链，然后用自己的代码实现课程要求。

- 不复制整个目录；
- 不把第三方仓库直接嵌进本仓库；
- 不因 Star 高就增加框架；
- 记录参考链接、版本、许可证和自己的取舍；
- 使用 [开源项目学习卡](resources/project-study-template.md) 证明自己真正理解。

## 什么时候算完成

不是看完 18 个 Markdown 文件，而是 [第 18 课验收清单](week-4/lesson-04.md) 全部通过。届时仓库应同时具有可复现代码、测试、引用可靠的周报、CI、定时任务、GitHub Pages 和清晰文档。
