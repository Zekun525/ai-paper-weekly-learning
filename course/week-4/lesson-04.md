# 第 18 课：成品验收、文档与演示

## 本课产物

形成一个别人能安装、运行、验证和理解的 GitHub 项目，而不只是你电脑上能跑的脚本。

## README 必须回答

1. 项目解决什么问题，目标用户是谁？
2. 数据从哪里来，完整架构是什么？
3. 如何用样例模式在 5 分钟内体验？
4. 如何配置真实 API 和模型？
5. 如何运行测试和自动任务？
6. 质量如何评测，有哪些已知局限？
7. 参考了哪些开源设计，哪些部分是自己实现的？

## 最终演示路线

1. 展示 GitHub Issue/PR 驱动的一次改动。
2. 从固定论文快照运行离线周报。
3. 展示一条带引用的跨论文结论。
4. 展示一次失败恢复或 Mock 替换。
5. 展示 CI、定时任务和 Pages 成品。
6. 用两分钟解释一个设计取舍，例如“为什么暂不引入完整 LangChain”。

## 最终验收清单

- [ ] 新环境可按 README 安装。
- [ ] 离线样例、测试和真实运行入口清楚分离。
- [ ] 密钥未进入仓库历史和日志。
- [ ] 论文采集可复现、可去重。
- [ ] 模型可以替换，默认测试不花钱。
- [ ] 综合结论带有效引用。
- [ ] 工作流有超时、预算、重试和恢复策略。
- [ ] CI 通过，Pages 可访问。
- [ ] 项目注明参考来源、许可证意识和自身贡献。

完成这份清单后再将项目标记为 v1.0。后续可选扩展包括浏览器 Agent、多 Agent 协作、Skill 系统和向量数据库，但它们都必须由新需求驱动。
